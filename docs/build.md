# Sources and rebuilding

The ready-to-run archive requires no Android compilation. These are optional
Linux developer instructions. Build archives are separate release assets so
ordinary users download only the runtime archive.

## Inputs

Clone this repository, then download `android12l-usb-sources-v0.1.0.tar.gz` and
`android12l-usb-build-inputs-v0.1.0.tar.gz` from releasev0.1.0. Check each asset
against the release SHA256SUMS, then from the repository root:

```sh
tar xzf android12l-usb-sources-v0.1.0.tar.gz --strip-components=1
tar xzf android12l-usb-build-inputs-v0.1.0.tar.gz --strip-components=1
sudo apt-get install build-essential bc bison flex libelf-dev libssl-dev libncurses-dev gcc-aarch64-linux-gnu libc6-dev-arm64-cross kmod device-tree-compiler e2fsprogs f2fs-tools dosfstools curl patch
mkdir -p logs prepared/android/arm64/modified
```

Sources archive: full upstream Linux, BusyBox and U-Boot sources. The Git
repository contains the complete current kernel patch, configurations, helper
source and upstream pins in `src/provenance.json`. The build-input archive
contains stock Android system partitions/ramdisks, the matching prebuilt kernel,
modules/vendor images, bootstrap binaries and build metadata. It contains **no
userdata, saved Wi-Fi, accounts or SPI backup**. `modified/vendor_a.img` is the
base vendor with USB-safe fstab and low-RAM properties; `vendor_usbnet_a.img`
adds the runtime helpers/features/Wi-Fi configuration. Both are included, so
regenerating the disk does not depend on unrecorded manual edits.

## Recreate the fresh disk using the included system inputs

```sh
bash tools/make-empty-filesystems.sh build/empty-filesystems
python3 tools/assemble-image.py --stock prepared/android/arm64 --filesystems build/empty-filesystems --layout src/disk-layout.json --output data/android-arm64.img
```

The assembler creates a new regular8GiB file/GPT, never reads old userdata,
checks filesystem types and LP checksums, and writes both matching vendor
extents. It refuses an existing output. Empty userdata is F2FS, metadata ext4,
and media_data FAT16, matching the first-stage fstab. GPT/filesystem UUIDs are
fresh, so the resulting whole-disk hash intentionally differs between builds.

## Rebuild the kernel and matching modules

The kernel source baseline is Orange Pi commit
`3a4a29414d558664847202f4d8919b8ab8bcf4a8`. `src/kernel.patch` was generated by
comparing all original source files against the actual built tree; it contains
the NBD platform parent, USB PIO, CFI linker placement and diagnostic/recovery
changes, including the runtime watchdog guard correction.

```sh
mkdir -p build/android-kernel-src build/android-kernel-usbnet-out
tar xzf sources/linux-upstream.tar.gz --strip-components=1 -C build/android-kernel-src
patch -d build/android-kernel-src -p1 < src/kernel.patch
cp src/kernel-usbnet.config build/android-kernel-usbnet-out/.config
python3 tools/fetch-android-clang12.py
bash tools/build-android-clang12.sh --usbnet
python3 tools/stage-android-cdc-kernel.py --usbnet
bash tools/build-android-cdc-modules.sh --usbnet
bash tools/build-android-uwe5622.sh
python3 tools/prepare-android-modules.py --usbnet --wifi-uwe5622
python3 tools/prepare-android-usb-vendor.py
```

Keep each kernel and its matching modules together. Import CRC checks reject
mismatched modules. The compiler is Android Clang r416183b1/12.0.7; the fetcher
verifies the selected compiler files against saved upstream Git blob IDs.
The two build scripts retain historical names; `--usbnet` selects the final
Ethernet-only profile. CFI table placement is checked during staging.

## Rebuild bootstrap helpers and RAM payload

```sh
mkdir -p build/busybox-1.36.1 prepared/storage
tar xjf sources/busybox-upstream.tar.bz2 --strip-components=1 -C build/busybox-1.36.1
cp src/busybox.config build/busybox-1.36.1/.config
make -C build/busybox-1.36.1 CROSS_COMPILE=aarch64-linux-gnu- olddefconfig
make -C build/busybox-1.36.1 CROSS_COMPILE=aarch64-linux-gnu- -j4
cp build/busybox-1.36.1/busybox prepared/android/arm64/busybox
for name in opi-watchdog opi-kmsg-forwarder; do
  aarch64-linux-gnu-gcc -static -O2 -Wall -Wextra tools/$name.c -o prepared/android/arm64/$name
done
aarch64-linux-gnu-gcc -static -O2 -Wall -Wextra tools/nbd-reverse-client.c -o prepared/storage/nbd-reverse-client-trace
python3 tools/prepare-android-usb-vendor.py
python3 tools/build-watchdog-bootloader.py
python3 tools/build-android-userspace.py --trace-nbd --live-kmsg
```

After rebuilding vendor/modules, assemble a **new** disk with the previous
section's command and a new output path. Never patch or rebuild a live disk.
The runtime release contains its matching boot manifest, bootloader, marker,
`prepared/linux/boot-usb.uEnv`, layout and verification scripts. Copy those small
unchanged inputs into your development checkout when rebuilding there; changed
payload files must use the newly generated manifest.

## Reproduce the Android filesystem measurement

This optional, bounded test creates a new 16 MiB file in a dedicated temporary
folder. It uses O_DIRECT to bypass the board page cache and refuses to overwrite
an existing test file. Host SSD caching still applies; this is not a cold-storage
or long-duration measurement. Run it after Android is ready:

```sh
mkdir -p build
aarch64-linux-gnu-gcc -static -O2 -Wall -Wextra tools/storage-benchmark.c -o build/storage-benchmark
adb -s 192.168.246.2:5555 push build/storage-benchmark /data/local/tmp/opi-storage-benchmark-bin
adb -s 192.168.246.2:5555 shell chmod 755 /data/local/tmp/opi-storage-benchmark-bin
adb -s 192.168.246.2:5555 shell 'mkdir -p /data/local/tmp/opi-storage-benchmark; timeout 70 /data/local/tmp/opi-storage-benchmark-bin /data/local/tmp/opi-storage-benchmark/run-$(date +%s).bin'
```

Results are JSON. Each run includes 16 MiB sequential writes/reads, 1,024 random
4 KiB reads, and 256 random 4 KiB writes with fsync. The program has a 60-second
alarm. These files are test data inside the disposable Android disk; do not copy
or publish the live disk to share a benchmark. [Measured results](validation.md).

## Android userspace and bootloader provenance

The stock system came from [OmniROM12.1v3 ARM64 tablet for Zero2W](https://github.com/YAJATapps/android_device_allwinner_apollo-p2/releases/download/v3/omni-12.1_20241209_arm64_zero2w.zip),
ZIP SHA256`330dabaf7332a2a5517d073834584eb70dd67552e5469ebfef81cf6dc8abf17e`.
[The upstream Android manifest/build instructions](https://github.com/YAJATapps/android_apollo-p2_local_manifest/tree/omni-12.1)
are the source for rebuilding the entire ROM; this project does not claim a
byte-for-byte rebuild of upstream Android userspace from a new repo sync.

The RAM bootloader is from MuntsOS commit
`899dcd98c001ec6278fb6fb35454340e46ce1ce6`, OrangePiZero2W boot bundle.
`src/uboot-Makefile`, `uboot.config`, `uboot.patch` and the full U-Bootv2024.10
source are supplied. Our build-watchdog helper changes only its control DTB;
SPL/U-Boot/TF-A executable bytes remain unchanged. The upstream TF-A recipe is
unpinned, so an exact bootloader rebuild is **not** claimed. Original recipe:
https://github.com/pmunts/muntsos/tree/899dcd98c001ec6278fb6fb35454340e46ce1ce6/boot/OrangePiZero2W/uboot

Release binaries have explicit SHA256s. Rebuilding with different host tools,
timestamps/UUIDs or upstream inputs can change hashes; first boot the new image
on hardware before treating it as validated. These build instructions preserve
the tested process but have not yet been rerun end-to-end in a clean build VM.
